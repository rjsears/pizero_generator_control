SECTION 1: PROJECT OVERVIEW
================================================================================

The RPi Generator Control system automates generator management for off-grid
solar installations. When your Victron Cerbo GX determines that battery levels
are low and generator power is needed, it sends a signal to GenMaster, which
coordinates with GenSlave to physically start the generator.

While designed around Victron integration, the architecture is universal—any
two-wire trigger source (home automation, PLC, manual switch, or relay output)
can signal GenMaster, and GenSlave can control any device with a two-wire
start input (generators, pumps, HVAC, irrigation, industrial equipment).

KEY FEATURES
------------

Automated Control:
- Victron Integration: Monitors GPIO signal from Cerbo GX relay
- Scheduled Runs: APScheduler-based scheduling with cron expressions
- Manual Override: Force start/stop from web UI regardless of Victron signal
- State Machine: Comprehensive state tracking (idle, starting, running, stopping)

Reliability & Safety:
- Automation Arming: Explicit arm/disarm prevents accidental operations
- Heartbeat System: Continuous health monitoring between GenMaster and GenSlave
- Independent Failsafe: GenSlave automatically stops generator if communication lost
- State Persistence: PostgreSQL database survives reboots and power failures

Generator Information & Fuel Tracking:
- Generator Profile: Manufacturer, model number, serial number
- Fuel Configuration: Fuel type (LPG, Natural Gas, Diesel) and expected load
- Per-Run Tracking: Automatically track fuel usage for each generator run

Exercise Scheduling:
- Automated Exercise: Schedule regular generator runs for maintenance
- Configurable Frequency: Weekly, bi-weekly, monthly, or custom

Modern Web Interface:
- Real-time Dashboard with live status updates
- Dark/Light mode support
- Mobile responsive design
- Container Management via Portainer integration

COMPONENT OVERVIEW
------------------

GenMaster (Raspberry Pi 5):
- Primary controller running Docker containers
- Monitors Victron signal on GPIO17
- Hosts web interface and REST API
- Maintains state in PostgreSQL database
- Sends heartbeats to GenSlave every 5 seconds
- Manages scheduling and notifications

GenSlave (Raspberry Pi Zero 2W):
- Secondary controller at generator location
- Controls relay via Automation Hat Mini (GPIO16)
- Displays status on built-in LCD
- Responds to GenMaster commands
- Runs independent failsafe monitor
- Auto-stops generator if communication lost for 30s

STATE MACHINE
-------------

The generator state machine handles all state transitions:

States:
- IDLE: Generator off, system waiting
- STARTING: Start command sent, waiting for confirmation
- RUNNING: Generator actively running
- STOPPING: Stop command sent, cleanup in progress

Triggers:
- VICTRON: Signal from Victron Cerbo GX
- MANUAL: User-initiated from web UI
- SCHEDULED: APScheduler-triggered run
- EXERCISE: Automated maintenance run

State Flow:

    IDLE -> [Trigger] -> STARTING -> RUNNING -> [Stop] -> STOPPING -> IDLE

State Transition Rules:
1. Start requires: automation armed, GenSlave connected, no override blocking
2. Running generator cannot be started again
3. Only running generator can be stopped
4. Override can force immediate stop regardless of trigger

HEARTBEAT PROTOCOL
------------------

Heartbeat Design:
- Interval: 5 seconds (configurable)
- Failure Threshold: 3 missed heartbeats = 15 seconds
- Failsafe Timeout: 30 seconds total

Protocol Flow:

    GenMaster                         GenSlave
        |                                 |
        |---- POST /api/heartbeat ------->|
        |     {                           |
        |       "timestamp": 1234567890,  |
        |       "generator_running": true,|
        |       "armed": true,            |
        |       "sequence": 42            |
        |     }                           |
        |                                 |
        |<-------- Response --------------|
        |     {                           |
        |       "relay_state": true,      |
        |       "armed": true,            |
        |       "last_heartbeat": ...,    |
        |       "sequence_ack": 42        |
        |     }                           |

Failsafe Behavior:

If GenSlave loses heartbeats for 30 seconds:
1. If relay is ON: Turn relay OFF immediately
2. Send failsafe notification via Apprise
3. Log failsafe event
4. Wait for heartbeat to restore

If GenMaster loses contact:
1. Mark GenSlave as disconnected
2. Send communication lost webhook
3. Block new start commands
4. When restored: sync state, send restored webhook

AUTOMATION ARMING SYSTEM
------------------------

The arming system prevents accidental operations during startup, maintenance,
or testing. Automation is DISARMED BY DEFAULT on boot.

Behavior by State:

    Event                    | DISARMED           | ARMED
    -------------------------+--------------------+------------------
    Victron signal HIGH      | Logged, no action  | Start generator
    Victron signal LOW       | Logged, no action  | Stop generator
    Scheduled run triggers   | Skipped, logged    | Execute normally
    Manual start request     | REJECTED           | Execute if valid
    Manual stop request      | Execute (safety)   | Execute
    Heartbeat failures       | Log only           | Full failsafe

Power Loss Recovery:
1. GenMaster boots with automation_armed = False
2. Generator state reset to not running
3. Orphaned run records closed with stop_reason = "power_loss"
4. Operator must explicitly arm system
5. GenSlave boots with relay OFF as safety measure

GENSLAVE SPECIFICATIONS
-----------------------

Computer: Raspberry Pi Zero 2W
HAT: Pimoroni Automation Hat Mini
Storage: Quality SD card or USB SSD
Power: 5V 2.5A supply
Relay: Built-in 24V @ 2A max (GPIO16)
Display: Built-in 0.96" 160x80 LCD

Memory Budget (512MB total):
- Linux OS: ~50MB
- Docker: ~100MB (Debian-based container)
- FastAPI + Uvicorn: ~40MB
- Tailscale: ~25MB (native)
- Total: ~215MB
- Available: ~297MB

AUTOMATION HAT MINI FEATURES
----------------------------

Relay Output:
- Type: Single-pole, double-throw (SPDT)
- Rating: 24V DC @ 2A max
- Controlled via: GPIO16

LCD Display:
- Size: 0.96 inch
- Resolution: 160x80 pixels
- Color: RGB
- Driver: ST7735

Inputs/Outputs:
- 3x ADC channels (not used in this project)
- 3x Digital outputs (not used)
- 1x Relay output (GPIO16)

VICTRON CONNECTION
------------------

Wire Type: 2-wire normally-open contact
From: Cerbo GX MK2 Relay output
To: GPIO17 (Pin 11) and Ground (Pin 9 or 14)
Pull-up: Internal pull-up resistor enabled on GPIO17

Signal Logic:
- Relay OPEN (normal): GPIO17 = HIGH (no generator needed)
- Relay CLOSED: GPIO17 = LOW (generator requested)

STATE MACHINE SERVICE
---------------------

File: app/services/state_machine.py

The StateMachine class manages all generator state transitions:

Key Methods:
- initialize(): Load state from database on startup
- start_generator(trigger, duration_minutes, notes): Start generator
- stop_generator(reason, notes): Stop generator
- handle_victron_signal_change(signal_active): Process GPIO changes
- enable_override(override_type): Enable manual override
- disable_override(): Disable manual override
- update_heartbeat_status(success, slave_status): Update heartbeat state
- get_full_status(): Return complete system status

State Transition Flow:
1. Validate transition is allowed
2. Send command to GenSlave
3. Create/update run record in database
4. Update system_state table
5. Log event
6. Send webhook notification

GPIO MONITOR SERVICE
--------------------

File: app/services/gpio_monitor.py

Monitors Victron signal on GPIO17 using gpiozero library:

    from gpiozero import Button

    victron_signal = Button(
        17,
        pull_up=True,
        bounce_time=0.1
    )

    # Signal LOW = Victron wants generator
    victron_signal.when_pressed = on_signal_active

    # Signal HIGH = Victron doesn't need generator
    victron_signal.when_released = on_signal_inactive

Mock GPIO Mode:
When not running on Raspberry Pi, automatically falls back to mock mode.
Development API available at /api/dev/* for simulating signals.

HEARTBEAT SERVICE
-----------------

File: app/services/heartbeat.py

Sends periodic heartbeats to GenSlave:

    async def _heartbeat_loop():
        while running:
            result = await send_heartbeat()
            await state_machine.update_heartbeat_status(
                success=result.success,
                slave_status=result.slave_status
            )
            await asyncio.sleep(interval)

    async def send_heartbeat():
        response = await slave_client.heartbeat(
            timestamp=int(time.time()),
            generator_running=state.generator_running,
            armed=state.automation_armed,
            sequence=sequence
        )
        return HeartbeatResult(
            success=True,
            latency_ms=latency,
            slave_status=response
        )

SCHEDULER SERVICE
-----------------

File: app/services/scheduler.py

Uses APScheduler for scheduled generator runs:

    scheduler = AsyncIOScheduler()

    def add_schedule(schedule: ScheduledRun):
        if schedule.recurring:
            trigger = CronTrigger.from_crontab(schedule.cron_expression)
        else:
            trigger = DateTrigger(run_date=schedule.scheduled_start)

        scheduler.add_job(
            execute_scheduled_run,
            trigger=trigger,
            id=f"schedule_{schedule.id}",
            args=[schedule.id]
        )

Auto-stop Feature:
When starting with duration_minutes, auto-stop is scheduled:

    scheduler.add_job(
        execute_auto_stop,
        DateTrigger(run_date=now + timedelta(minutes=duration)),
        id=f"auto_stop_{run_id}"
    )

    import automationhat

    class RelayService:
        def __init__(self):
            self._state = False
            self._armed = False
            self._last_on_time = None

        def relay_on(self, force=False):
            """Turn relay ON. Requires armed unless force=True."""
            if not self._armed and not force:
                raise NotArmedError("Relay not armed")
            automationhat.relay.one.on()
            self._state = True
            self._last_on_time = time.time()
            self._update_lcd()

        def relay_off(self, force=False):
            """Turn relay OFF. Always allowed for safety."""
            automationhat.relay.one.off()
            self._state = False
            self._update_lcd()

        def arm(self):
            """Arm the relay for remote control."""
            self._armed = True
            self._update_lcd()

        def disarm(self):
            """Disarm the relay. Relay can still be turned OFF."""
            self._armed = False
            self._update_lcd()

        def get_state(self):
            """Get current relay state."""
            return self._state

    from PIL import Image, ImageDraw, ImageFont
    import ST7735

    class LCDService:
        def __init__(self):
            self.display = ST7735.ST7735(
                port=0,
                cs=ST7735.BG_SPI_CS_FRONT,
                dc=9,
                backlight=25,
                rotation=270,
                spi_speed_hz=4000000
            )
            self.width = 160
            self.height = 80

        def update(self, relay_state, armed, last_heartbeat, ip_addr):
            image = Image.new('RGB', (self.width, self.height), (0, 0, 0))
            draw = ImageDraw.Draw(image)

            # Draw status
            relay_text = "RELAY: ON" if relay_state else "RELAY: OFF"
            color = (0, 255, 0) if relay_state else (128, 128, 128)
            draw.text((5, 5), relay_text, fill=color)

            # Draw armed state
            armed_text = "ARMED" if armed else "DISARMED"
            armed_color = (0, 255, 0) if armed else (255, 165, 0)
            draw.text((5, 25), armed_text, fill=armed_color)

            # Draw heartbeat
            hb_text = f"HB: {last_heartbeat}s ago"
            draw.text((5, 45), hb_text, fill=(200, 200, 200))

            # Draw IP
            draw.text((5, 65), ip_addr, fill=(100, 100, 100))

            self.display.display(image)

FAILSAFE SERVICE
----------------

File: app/services/failsafe.py

Monitors heartbeats and triggers failsafe if communication lost:

    class FailsafeService:
        TIMEOUT_SECONDS = 30  # Failsafe triggers after 30s

        def __init__(self, relay_service, notification_service):
            self._relay = relay_service
            self._notifier = notification_service
            self._last_heartbeat = time.time()
            self._failsafe_active = False
            self._running = False

        async def start(self):
            self._running = True
            asyncio.create_task(self._monitor_loop())

        async def _monitor_loop(self):
            while self._running:
                elapsed = time.time() - self._last_heartbeat

                if elapsed > self.TIMEOUT_SECONDS:
                    if not self._failsafe_active:
                        await self._trigger_failsafe()

                await asyncio.sleep(1)

        async def _trigger_failsafe(self):
            self._failsafe_active = True

            # Turn off relay if it's on
            if self._relay.get_state():
                self._relay.relay_off(force=True)
                logger.warning("FAILSAFE: Relay turned OFF due to lost heartbeat")

            # Send notification
            await self._notifier.send_failsafe_alert()

        def receive_heartbeat(self, timestamp, generator_running, armed):
            """Called when heartbeat received from GenMaster."""
            self._last_heartbeat = time.time()
            self._failsafe_active = False

            # Sync armed state from GenMaster
            if armed and not self._relay._armed:
                self._relay.arm()
            elif not armed and self._relay._armed:
                self._relay.disarm()

            # Sync relay state from GenMaster
            if generator_running and not self._relay.get_state():
                self._relay.relay_on()
            elif not generator_running and self._relay.get_state():
                self._relay.relay_off()

    class RebootScheduler:
        CHECK_INTERVAL = 60  # Check every minute

        def __init__(self):
            self._running = False
            self._relay_service = None
            self._last_reboot_date = None

        def get_schedule(self):
            """Get current reboot schedule."""
            raw = db_service.get_setting("reboot_schedule")
            if raw:
                return json.loads(raw)
            return {
                "enabled": False,
                "day": "sunday",
                "hour": 4,
                "minute": 0
            }

        def set_schedule(self, enabled, day, hour, minute):
            """Set reboot schedule."""
            schedule = {
                "enabled": enabled,
                "day": day.lower(),
                "hour": hour,
                "minute": minute
            }
            db_service.set_setting("reboot_schedule", json.dumps(schedule))

        def _is_safe_to_reboot(self):
            """Check if generator not running."""
            return not self._relay_service.get_state()

        def _execute_reboot(self):
            """Execute host reboot using nsenter."""
            if self._relay_service:
                self._relay_service.relay_off(force=True)

            # Reboot host from within container
            subprocess.Popen(
                ["nsenter", "-t", "1", "-m", "-u", "-i", "-n", "/sbin/reboot"],
                stdout=subprocess.DEVNULL,
                stderr=subprocess.DEVNULL,
                start_new_session=True
            )

Note: Host reboot requires docker-compose.yaml settings:

TAILSCALE SETUP
---------------

Tailscale creates a secure mesh VPN using WireGuard encryption.

Why Tailscale:
- Creates stable 100.x.x.x IPs for all devices
- Works through NAT and firewalls
- MagicDNS provides hostname resolution
- Minimal resource usage (~25-50MB RAM)
- Zero-config peer-to-peer connections

Network Architecture:

    Your Devices (Phone, Laptop)
              |
    Tailscale Mesh Network (WireGuard)
              |
    +----+----+----+
    |    |         |
    v    v         v
    GenMaster  GenSlave  n8n
    100.x.101  100.x.102 100.x.50

Setup on GenMaster (Docker):
1. Enable tailscale profile in docker-compose
2. Set TAILSCALE_AUTHKEY in .env
3. Start container: docker compose --profile tailscale up -d

Setup on GenSlave (Native):
1. Install Tailscale: curl -fsSL https://tailscale.com/install.sh | sh
2. Authenticate: sudo tailscale up --authkey=<key> --hostname=genslave

ACL Configuration (Tailscale Admin Console):
    {
      "acls": [
        {
          "action": "accept",
          "src": ["tag:admin"],
          "dst": ["tag:generator:*"]
        },
        {
          "action": "accept",

NGINX GEO ACCESS CONTROL
------------------------

The nginx geo module classifies requests as internal or external:

    geo $access_level {
        default          "external";
        127.0.0.1/32     "internal";
        10.0.0.0/8       "internal";
        172.16.0.0/12    "internal";
        192.168.0.0/16   "internal";
        100.64.0.0/10    "internal";  # Tailscale CGNAT
    }

Protected endpoints (Portainer) check access level:

    location /portainer/ {
        if ($access_level = "external") {
            return 403;
        }
        proxy_pass http://genmaster_portainer/;
    }

SECTION 13: UTILITIES (WIFI WATCHDOG)
================================================================================

OVERVIEW
--------

wifi-watchdog.sh monitors WiFi connectivity and automatically recovers
from connection failures. Designed for both GenMaster and GenSlave.

FEATURES
--------

- Auto-detects default gateway (no hardcoded IPs)
- Auto-detects WiFi interface (wlan0, wlp2s0, etc.)
- Escalating recovery (soft fixes before hard resets)
- Reboot protection (max one reboot per hour)
- State persistence across restarts
- Works on Pi 5 and Pi Zero 2W

RECOVERY SEQUENCE
-----------------

    Consecutive Failures | Action
    --------------------+------------------------------------------
    1-3                 | Soft WiFi reset (nmcli/wpa_cli)
    4-5                 | Hard WiFi reset (ip link down/up)
    6+                  | System reboot (once per hour max)

INSTALLATION
------------

Manual installation:
    sudo cp wifi-watchdog.sh /usr/local/bin/
    sudo chmod +x /usr/local/bin/wifi-watchdog.sh
    sudo cp wifi-watchdog.service /etc/systemd/system/
    sudo systemctl daemon-reload
    sudo systemctl enable wifi-watchdog
    sudo systemctl start wifi-watchdog

Check status:
    sudo systemctl status wifi-watchdog
    sudo journalctl -u wifi-watchdog -f

CONFIGURATION
-------------

Edit /etc/systemd/system/wifi-watchdog.service:

    Variable                    | Default | Description
    ----------------------------+---------+-----------------------------
    WATCHDOG_CHECK_INTERVAL     | 30      | Seconds between checks
    WATCHDOG_PING_TIMEOUT       | 5       | Ping timeout in seconds
    WATCHDOG_PING_COUNT         | 2       | Pings per check
    WATCHDOG_MAX_SOFT_RESETS    | 3       | Soft resets before escalating
    WATCHDOG_MAX_HARD_RESETS    | 2       | Hard resets before reboot
    WATCHDOG_REBOOT_COOLDOWN    | 3600    | Min seconds between reboots

SECTION 14: SCHEDULED REBOOT
================================================================================

OVERVIEW
--------

GenSlave supports scheduled maintenance reboots to ensure system stability.
The reboot scheduler runs inside the Docker container and can reboot
the host system using nsenter.

REQUIREMENTS
------------

docker-compose.yaml must include:
    privileged: true
    pid: host

These settings allow the container to access the host namespace
and execute the reboot command.

CONFIGURATION
-------------

Via API:
    POST /api/reboot/schedule
    Body: {
        "enabled": true,
        "day": "sunday",      # monday-sunday or "daily"
        "hour": 4,            # 0-23
        "minute": 0           # 0-59
    }

Via Environment:
    REBOOT_SCHEDULE_ENABLED=true
    REBOOT_SCHEDULE_DAY=sunday
    REBOOT_SCHEDULE_HOUR=4
    REBOOT_SCHEDULE_MINUTE=0

SAFETY FEATURES
---------------

1. Generator Running Check: Will not reboot if relay is ON
2. Daily Limit: Only one reboot attempt per day
3. Skip on Busy: If generator running at scheduled time, skips that day
4. Relay Safety: Turns OFF relay before rebooting (if somehow still on)

IMPLEMENTATION
--------------

The reboot is executed using nsenter to access the host namespace:

    subprocess.Popen(
        ["nsenter", "-t", "1", "-m", "-u", "-i", "-n", "/sbin/reboot"],
        stdout=subprocess.DEVNULL,
        stderr=subprocess.DEVNULL,
        start_new_session=True
    )

Parameters:
- -t 1: Target PID 1 (host's init process)
- -m: Enter mount namespace
- -u: Enter UTS namespace
- -i: Enter IPC namespace
- -n: Enter network namespace

SECTION 16: TROUBLESHOOTING
================================================================================

COMMON ISSUES
-------------

GenSlave shows offline:
    Run: ./setup.sh --genslave
    This validates DNS, ping, port, and API health

GenSlave IP changed:
    Run: ./setup.sh --genslaveip
    Updates the URL in .env and restarts containers

Generator won't start:
    1. Check GenSlave is online
    2. Verify automation is armed
    3. Check for active override (force_stop)
    4. Check GenSlave relay arm status

Victron signal not detected:
    1. Check GPIO17 wiring
    2. Test with development API:
       curl http://localhost:8000/api/dev/gpio/state
    3. Verify not in mock GPIO mode when on real hardware

Container won't start:
    Run: docker compose logs <container>
    Common causes:
    - Port already in use
    - Volume permission issues
    - Environment variable missing

Database connection failed:
    1. Check DATABASE_PASSWORD matches in both services
    2. Verify db container is healthy:
       docker compose ps db
    3. Check PostgreSQL logs:
       docker compose logs db

LXC Docker issues:
    Add to container config (/etc/pve/lxc/<id>.conf):
    - lxc.apparmor.profile: unconfined
    - lxc.cgroup.devices.allow: a
    Restart container after changes

API key mismatch:
    1. Update SLAVE_API_SECRET in GenMaster .env
    2. Update API_SECRET in GenSlave .env
    3. Restart both: docker-compose up -d --force-recreate

USEFUL COMMANDS
---------------

View all container logs:
    docker compose logs -f

View specific container:
    docker compose logs -f genmaster

Restart container:
    docker compose restart genmaster

Check database:
    docker compose exec db psql -U genmaster -d genmaster
    SELECT * FROM system_state;
    SELECT * FROM generator_runs ORDER BY id DESC LIMIT 5;

Test GenSlave manually:
    curl -H "X-API-Key: <secret>" http://genslave.local:8001/api/health

Check GPIO state (mock mode):
    curl http://localhost:8000/api/dev/gpio/state

Run database migrations:
    docker compose exec genmaster alembic upgrade head

Backup database:
    docker compose exec db pg_dump -U genmaster genmaster > backup.sql

Force recreate containers:
    docker compose up -d --force-recreate

Pull latest images:
    docker compose pull && docker compose up -d

LOG LOCATIONS
-------------

GenMaster application: docker compose logs genmaster
Nginx access: docker compose logs nginx
PostgreSQL: docker compose logs db
Container logs in container: /app/logs/

SECURITY BEST PRACTICES
-----------------------

1. Change all default passwords in .env
2. Use Tailscale for remote access instead of exposing ports
3. Enable Cloudflare Access for additional authentication layer
4. Regularly update Docker images
5. Monitor failed login attempts in logs
6. Use strong API secrets (generated by setup.sh)
